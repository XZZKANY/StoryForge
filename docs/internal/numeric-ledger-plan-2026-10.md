> **作者 2026-10-31 已审**（6 问的拍板见第 11 节）。起草 2026-10-30，依据 master `93dc4bd0`。只写了这份文档：没改代码，没跑模型。文中行号以后会漂。

- 实验证据来自本机实验台 `output/drift-lab/`（不入库），主要是 `REPORT.md` 第一、七、七之二、十节，和回放数据 `replay/out/cn_facts.jsonl`。

## 0. 先说结论

1. **做什么。** 检查器本来就在顺带抽「数值」类事实。让它对每个数多交几个结构化的数（变动前、增减、变动后），并且只许抄原句里写出的数。程序按章把账算一遍，正文写出的数和账上的对不上就标出来，交给作者三选一：改正文（程序只改那一个数）、以正文为准、改成别的数。
2. **不加模型调用。** 抽数捎在现有的检查调用里；算账、比对、改数都是程序做的。
3. **为什么这样做。** 实验里只有经作者核对的账有效：数值偏离大纲从 57%（不记账）降到 19%（作者核对的账）。跟着正文自动记的账是 54%，几乎没用；不经核对的自动账是 66%，反而更差。但作者每章都核太累，而且章纲已经不停下等确认了（#531）。所以这里的做法是**程序记账、程序算平、只把算不平的地方交给作者**。这个折中能不能接近 19%，实验没测过，所以第一刀是实验（刀 0），过线才动产品。
4. **在哪报。**
   - 写章检查完，回复里先出一句程序提示，不拦稿、不触发修复。
   - 写进文件后记账时再算一遍，对不上的计入「对不上」条数。批量写章照作者定的规矩（第 6 问 A）停在这一章。
   - 观测镜里多一块「账」，在那里处理。
5. **起草带什么。** 带按账算到上一章末的数，一账一行；对不上、还没定的那一处不当权威。
6. **先不做。** 境界、等级这类不能加减的写法；年龄、倒计时（故事时钟）；写完自动改数；一次改多章的数。
7. **分刀与提问。** 刀 0 是实验，刀 1–5 动产品，刀 6 是真模型小跑（先问作者）。要作者定的 6 个问题在第 9 节。

## 1. 核实过的现状

### 1.1 台账今天怎么记数

- 检查器抽「本章新定下的事实」，分 7 类，数值是其中一类，值是一段自由文字（`packages/engine/src/loop/chapterCheckProtocol.ts:76` 的 `NEW_FACTS_SPEC`）。老章补录用同一段指令（`:85`）。
- 记账时，数值、持有、处境、身份这几类的新值直接替代旧值，不做任何核对（`kernel/factLedger.ts:287-299`）。只有生死、关系、来历和别章对不上，才存成待定（`:273`）。**所以正文把余额写错了，台账就照记错的数**。这正是实验里「跟着正文走的账」54% 的成因。
- 同一属性已有一条同值的有效事实时，后面再出现就当重复，不记（`:260-271`）。对账来说，这会丢掉第二次「+15」。
- 起草带「已写事实」时，只取「现在仍有效」的事实，一条一行「主体 · 类别/属性：值（第 N 章「原句」）」（`kernel/canonContext.ts:244-310`，行格式在 `:293`）。写第 10 章时如果第 20 章已经写过，带的是第 20 章的数，不是第 9 章末的数。

### 1.2 检查器实际抽出来的数长什么样

回放的 400 章（`replay/out/cn_facts.jsonl`），四种题材，正文取自实验台的引擎长篇：

- 2970 条事实里数值 173 条（约 6%），其中 170 条带数字，39 条看得出是增减。
- 变动前、增减、余额常挤在一个值里：「缴验伤费用470元后余额19465元」「455点（本章消耗80点）」「1990→2370」「增加15点后为23点」。
- 也有不该算账的数：体温、半衰期、页数、执掌年数、匹配度。
- 账名不稳：同一个进化点，有时叫「进化点」，有时叫「吞噬海尸获得进化点」。
- 原句里常带约数：「划走八百多」「剩六千八百多」「二十来个」。

### 1.3 作者手记过的账

作者自己的连载作品里，`canon.json` 有一段作者手加的数值账，7 月中旬之后没再动过。它按章记开章和章末的点数、买了什么、花了多少，备注里写明程序不读也不校验。本设计要做的，就是让程序替作者记这本账，而且真的去读、去校验。

### 1.4 作者能核对的点只剩写进文件之后

- #531 合并后，章纲拟好不再停下等确认，同一次运行里接着起草（`loop/chapterWritingPipeline.ts:269-281`）。实验里「作者在章纲卡片上把数改对」那组（E1，偏离 13–26%）用的那条路，在产品里已经不在了。
- 剩下的核对点：写章回复里的程序提示、写进文件后的记账提示、观测镜。

### 1.5 批量写章遇到「事实对不上」会停

作者 10-30 定的第 6 问选 A：记事实时和已记的事实对不上就停，等作者在观测镜里定了再续（`docs/internal/write-batch-plan-2026-10.md:319`、`:553`）。批量记录里每章有 `fact_disputes` 计数（`loop/writeBatchRecord.ts:122`）。

### 1.6 实验结论（只列和本设计有关的）

长程 24 章 × 4 本书（`REPORT.md` 第七、十节）：

| 记账方式 | 数值偏离大纲 |
|---|---|
| 不记账（产品现状） | 57% |
| 不经核对的自动账 | 66% |
| 跟着正文走的账（据正文核对） | 54% |
| 起草时让模型自报变化 | 53% |
| 全文塞进上下文 | 62% |
| 作者核对过的账 | **19%** |
| 作者核对过的账 + 程序代写数字 | 12.5%（和 19% 的差在误差内） |

另外几条：

- 报告原话：「典型过程是前几章某处算错一次，之后再也回不来」。所以要在第一次算错的那一章抓住。
- 报告原话：「核对账把状态拉回大纲却没改掉已经写偏的正文，会产生跳变」。所以改账要配着改正文。
- 程序代写数字只在阿拉伯数字的写法上有效；「炼气五层」这类写法，模型一次都没配合（0/24）。
- 局部修和整章重写修好率相当，改动量只有十几分之一。
- 局限：模型只有国产三家，没有作者实际用的模型；大纲是合成的；长程只跑了 1 个种子。

## 2. 账是什么

### 2.1 账与分录

- **账**：一个主体身上一项会加减的数，比如陈默的进化点、陈野的账户余额、一箱纽扣的数量。
  - 账的键 = 主体 + 账名。
  - 主体按 `canon.json` 的别名归一，和现在记账用同一张表；账名用 `factKey` 的归一。
- **分录**：正文里的一句原句，带下面几个可选字段。
  - `from`：这句写出的变动前的数。
  - `change`：这句写出的增减，增为正、减为负。
  - `balance`：这句写出的变动后的数，或者「当前多少」。
  - `unit`：单位，只用来显示。
  - `approx: true`：这句的数是约数（八百多、上百、二十来个），只记不核。
- **作者裁定**：作者认定「这一处是 X」。记成一条没有原句的分录：
  - `recorded_by: "author"`、`assertion_type: "author_ruling"`，只有 `balance`；
  - 用 `ruling_for` 指向被裁定的那条分录，位置就算在那一句上。

### 2.2 什么样的数值算账

- 同一个键至少出现过一次 `change`，才算账。
- 只出现过「当前多少」的数（年龄、体温、页数）照旧当普通数值事实，不算账、不报警。
- 理由：会漂的是流动的数（点数、余额、库存）。只写过「当前多少」的数，没法知道它该不该变，硬算只会误报。年龄这类随时间变的数，留给以后的故事时钟。

### 2.3 存在哪

- 不另开文件，就存在 `facts.json` 的 `facts` 里，数值事实多一个 `amount` 字段。
- 旧版程序读到不认识的字段会原样保留：`checkFactLedger` 只校验认识的字段，记账时整条复制。
- 不另开 `accounts.json` 有两个理由：讨论定的方向是「只留一本账」；台账现有的原句核对、作废、依据失效、写前快照和撤销都能直接用上。

一条正文里的分录：

```json
{
  "id": "fact_3f9a1c0d2b7e",
  "kind": "数值",
  "subject": "陈默",
  "attribute": "进化点",
  "value": "吞噬后+20，当前60",
  "object": null,
  "path": "正文/第013章.md",
  "status": "active",
  "amount": { "from": null, "change": 20, "balance": 60, "unit": "点" },
  "assertion_type": "text_observation",
  "recorded_by": "auto",
  "evidence": [{ "path": "正文/第013章.md", "quote": "【吞噬完成。进化点+20。当前进化点：60。】", "start_line": 23 }],
  "recorded_at": "2026-11-02T08:00:00Z"
}
```

一条作者裁定：

```json
{
  "id": "fact_8c2e7a91d0f4",
  "kind": "数值",
  "subject": "陈默",
  "attribute": "进化点",
  "value": "作者认定此处为 200",
  "object": null,
  "path": "正文/第013章.md",
  "status": "active",
  "amount": { "balance": 200 },
  "assertion_type": "author_ruling",
  "recorded_by": "author",
```

## 3. 怎么抽

### 3.1 检查器多交什么（改检查提示词，先要回放证据）

在 `NEW_FACTS_SPEC` 里给数值类加一段（草案，措辞在刀 0 里量）：

> 数值类另给 amount：from（这句写出的变动前的数）、change（这句写出的增减，增为正、减为负）、balance（这句写出的变动后或当前的数）、unit（单位）。只能填这句原文里写出的数，没写出的填 null，不要自己算；约数（八百多、上百、二十来个）不填数，填 approx: true。attribute 只写账名（如进化点、余额），不写事件。

两处可选，刀 0 对比后再定：

- 把这本书已有的账名（最多 20 个）附在提示词里，让检查器沿用同一个名字。
- 数值类单独算条数上限（比如 10 条），不占原来 15 条的名额。

老章补录用的是同一段指令，所以补录也会自动抽数。

### 3.2 程序怎么核

- **每个数都得在原句里找得到。**
  - 程序先把原句里的数都认出来：阿拉伯数字（含全角、千分位逗号、小数）、中文数字（含万、亿、零、〇、两）、混写（1.5万）。
  - 口语省略照口语读：一万五 = 15000，三千二 = 3200。
  - `from`、`balance` 和 `change` 的大小必须各等于其中一个数。哪个字段对不上就丢掉哪个，这条事实照旧记（坏了只丢这一项，和现在的规矩一样）。
- **正负号由模型给，大小由原句证明，差额由程序算。** 比如「余额跳到15220」只认 `balance: 15220`。模型如果自己算出 `change: -265`，原句里没有 265，就丢掉。
- 带「几」的（十几、几十），以及前后带「多、来、余、上下、左右、出头、约、近」的数，一律当约数。
- 记账时对写进文件后的正文再核一次，沿用现有 `candidateOf` 的做法（`loop/factRecord.ts:46`）。

### 3.3 记账的两处小改（`planFactRecord`）

- 带 `amount` 的数值事实按「同一章、同一句原句」去重，不再按值去重。
- 替代链照旧：新的替代旧的，旧的标 superseded 留着。账不看替代链，每次都从全部未作废、依据仍在的分录重新算。

## 4. 怎么算

一个账的分录按阅读序排好（先按章序，再按原句起始行），从头算一个「账上的数」r：

| 这一句写了什么 | 怎么核 | 对不上时报什么（举例） |
|---|---|---|
| 变动前 `from` | `from` 和 r 比 | 「本章开头写成 61，上一处是 58」 |
| 增减 `change`（可能还有 `balance`） | `balance` 和（`from` 或 r）+ `change` 比 | 「上一处 150，这里 +30，应为 180，写成 200」 |
| 只有 `balance` | `balance` 和 r 比 | 「上一处 150，这里写成 200，中间没写怎么来的」 |
| `from` 和 `balance`（如「1990→2370」） | 只核 `from`，增减是明写的 | 同第一行 |

规矩：

- **一句最多报一处**，报最靠前的原因（开头就不对，就只报开头）。
- **对不上的那句不当权威。** r 按账接着算（有增减就加上增减），不跟着正文写的数走；作者裁定了，r 才改成裁定的数。实验里「跟着正文走的账」没用，就是因为一句写错、后面全跟着错。
- **约数断账。** 遇到约数，r 变成「不知道」，到下一个确数再接上，中间不报。
- **没记账的章断账。** 两句之间隔着没记过账的章（作者手写的、还没补录的），r 变成「不知道」，不报。账上标「第 a–b 章没记账，账在这里断开，可以先补录」。
- **作废的、依据已失效的分录不算。** 作者在编辑器里手改了那个数，原句就找不到了，这条自动不算，账按剩下的分录算。
- **起点不报。** 账上第一个确数（不管来自 `from` 还是 `balance`）就是起点。
- **每处对不上有固定 id**，由那条分录的 id 算出，观测镜跨次扫描能认出是同一处。
- **连锁合成一组。** 连着几处对不上、差额都一样（多半是上游某章改过），合成一组显示「从第 5 章起差 10，后面 8 处跟着对不上」，指向最早那一处。

**对不上不存成状态。** 生死那几类对不上会存成「待定」，账不这样：账的对不上每次都从分录重算。作者改了正文、作了裁定、作废了抽错的分录，下次一算就没了；上游某章改了，下游哪几处跟着对不上，也会自动算出来。

## 5. 在哪报、怎么处理

### 5.1 写章检查之后（检查步骤里，程序算）

- 检查器交回新事实后，程序读台账，把本章草稿的分录接到账上算。对不上的作为程序提示 `account_mismatch` 加进检查结果，归进 `PROGRAM_ADVISORY_RULES`（`chapterCheckProtocol.ts:37`）。
- 程序提示不拦稿、不进修复，回复里出一句，例如：「程序提示：陈默的进化点上一处是 150，本章 +30 应为 180，第 23 行写成 200。」
- 先不当硬伤修，原因有二：
  - 实验里由 deepseek 来查时，检查器报的硬伤 84% 不成立；这里的报警准不准，要刀 0 量过才知道。
  - 当硬伤会触发修复，多一次模型调用，还可能改动别处。

### 5.2 写进文件、记账时（`loop/factRecord.ts`）

- 用写进文件后的正文再算一遍。本章新出现的对不上计入「对不上」条数（批量记录的 `fact_disputes`）。
- 接受提示里说：「进化点对不上：按账 180，正文写 200，等你在观测镜里定」，带一个「去看看」。
- 批量写章照第 6 问 A 停在这一章。

### 5.3 观测镜「事实台账」分区里多一块「账」

每个账一张卡，平时折叠，只显示当前数；有对不上的就展开并标出来：

```
陈默 · 进化点                               截至第 13 章末：180 点
  第 12 章   期末 150      「……进化点：150。」
  第 13 章   +30 → 180    「吞噬完成。进化点+30。」
             正文写 200   「当前进化点：200」   ✗ 按账应为 180
             [改正文 200→180]  [以正文为准]  [改成…]
```

- **改正文**：
  - 程序只改这句里的那一个数（开头不对时改两个），照原来的写法写：阿拉伯数字照阿拉伯，中文数字照中文，全角照全角。
  - 打开这一章，把这一处作为一份修订摆出来，对比里只有这一个数。按权限档位接受、写进文件，和别的修订同一条路（写前快照、版本记录、可撤销）。
  - 写进去后，台账里那条分录的原句和数换成改后的（走 `lib/fact-write.ts`，可撤销）。
  - 这句里同一个数出现两次，或者原来的写法还原不出来时，按钮灰掉并说明原因，请作者手改。
- **以正文为准**：记一条作者裁定，`balance` 等于正文写的数，账从这里接着算。
- **改成…**：作者填一个数，记成作者裁定。正文和它不一样时仍然标着，再给一个「改正文」，改成作者填的数。
- **抽错了**（数挂错了账）：用现有的「作废」。
- 连锁那一组这一步只能逐处改。

### 5.4 批量写章的清单

批量结束后统一审的清单（批量方案第 7 节）多一行「账对不上 K 处」。

## 6. 起草带什么

- 章纲、起草、整章修订带「已写事实」时，属于账的数值事实不再一条条带，改成一账一行，带按账算到**上一章末**的数：

  ```
  - 陈默 · 数值/进化点：180点（按账算到第 13 章末：第 12 章末 150，第 13 章 +30）
  ```

- 对不上、还没定的那句不带，账照算出的数带。这和固定事实「待定的不进起草、旧值照旧有效」是同一个规矩。
- 按章取当时的数：写第 10 章就带第 9 章末的数，哪怕第 20 章已经写过。
- 账在末尾断开时（约数、没记账的章），不带这一账；起草时本来就看得到上一章正文。
- 章纲那边已经让模型找「要花的钱超过账上剩的」（`chapterWritingContracts.ts:314`）。换成算好的数以后冲突更容易看出来，所以章纲提示词不另改。
- 这是起草提示词的改动，照 `CLAUDE.md` 先做回放对比（同 10-18 的 `draft_cn` 做法）。golden 用以前的核对做法，证明只变了账那几行。

## 7. 先不做

| 不做什么 | 为什么 |
|---|---|
| 境界、等级这类不能加减的写法（炼气五层、筑基初期） | 要作者先定一条梯子，另开题；实验里模型对这类写法也不配合 |

| 每章多一次模型调用、改检查的拦稿规则 | 作者定过不加每章调用 |

## 10. 风险与反对意见

- **作者不处理报警。** 单章写不拦，只提示。起草带的是账上的数，正文里写错的那句还在，读者会看到跳变（实验里已经见过）。批量会停。
- **抽错一个数就是一次误报。** 模型把数挂错了账（账名不稳）就会误报。刀 0 量，过不了线就不接报警。
- **会漏报。** 约数、单位不同、「两笔加起来」这类写法都不核。宁可漏报，不误报。
- **起草提示词改动可能有副作用。** 实验里往提示词加的东西越多，漏接钩子越多。所以只换账那几行、不加新段落，刀 5 附回放对比。
- **只在数字多的书里有用。** 回放里数值只占约 6%，非数值题材几乎不触发，代价也接近零。
- **抓不到「自洽但偏离计划」。** 正文自己算得平，只是多了一笔计划里没有的消费（实验里核对账组剩下的错多半是这种），这一步抓不到。那要作者看计划，或者检查器对照章纲。

## 12. 刀 0 结果（2026-10-31）：没过线，停在这里

实验脚本与原始结果在工作区 `output/numeric-ledger/`（不入库）。

### 12.1 跑了什么

- 模型：原来的 deepseek 中转 key 已停用（403），作者同意改用备用中转上的 claude-sonnet-5，也就是作者平时写作用的模型。
- 材料：实验台引擎长篇 E0 四本书（末世、仙侠、都市、悬疑）各第 1–40 章，配当时作者确认过的章纲；提示词和校验直接用引擎源码，和产品一字不差。
- 新版（加 amount 那段）：160 章。
- 旧版对照：每本书前 10 章，共 40 章，和新版一一配对。原计划 160 章，因为 sonnet-5 每次检查实际要 6000–7500 token，为了守住 250 万上限缩小了。
- 附已有账名：末世、都市两本各 40 章，按章顺序跑，每章附上前面各章出现过的账名。
- 报警复核：8 处全部复核，复核模型（同一个 sonnet-5）的结论有自相矛盾，最终以我逐条读原文为准。
- 「第一次偏离」：用当时评测记下的「每章正文写成多少」对照大纲真值找出来，再逐个读原文核实。

### 12.2 对照通过线

| 通过线 | 结果 | |
|---|---|---|
| 数在原句里核得上 ≥ 95% | 76%（178 个数核上 135 个）：余额 93%，增减 65%，变动前 33%。模型常把自己推算的数填进去 | 没过 |
| 报警成立 ≥ 80% | 3/8。成立的 3 处报的位置和「应为」都不准，因为真正出错的那句没被抽到 | 没过 |
| 第一次偏离抓到 ≥ 50% | 0/5。核原文后，5 处里有 3 处其实是评测误读（另一个数、人物的问话），1 处正文自洽、只是和大纲不同（按设计本来抓不到），1 处是暗含的总数（「再碰上一只，攒够二十点」暗示手里只剩 10 点，前文应为 18） | 没过 |
| 每 10 章误报 ≤ 1 次 | 约 0.3 次。低是因为抽得少、报得少，不说明准 | 过，但不说明问题 |
| 检查的硬伤条数、作废率变化在误差内 | 配对 40 章：硬伤 0.23 → 0.13 条/章，作废 1/40 → 3/40（样本小）。**每章抽出的事实 8.9 → 6.3 条，37 章里 28 章变少** | 没过 |

### 12.3 为什么不行

1. **检查器不会把每一笔进出都抽出来。** 它抽的是「本章新定下的事实」，每章只抽 0.9 个数。人数、物件这类基本抽不到：末世的幸存者人数，评测里 7 章写到，只抽到 1 章；仙侠的玉简 19 章写到，只抽到 3 章。
2. **少抽一笔，后面就全对不上。** 漏抽的增减让余额「无故跳变」，同一章后面的余额跟着连环报警；同一个数换个名字（「账户余额」「外卖平台账户余额」）就拆成两个账，各算各的。
3. **模型不守「只填原句里的数」。** 余额基本照抄，增减和变动前多半是它算出来的，程序只能丢掉，账就缺了这几笔。
4. **这批稿子里，数值的错大多不是「正文自己算错」。** 更多是「和计划不一样，但前后自洽」，或者「暗含的总数」，按账算都抓不到。正文明写出来的自相矛盾很少：8 处报警背后只有 3 处。
5. **捎带有代价。** 加了这段说明以后，检查器整体抽事实少了三成。这会削弱已经证明有效的事实台账（相邻章矛盾 36% → 22%）。

### 12.4 附已有账名（末世、都市各 40 章）

| | 新版 | 附账名 |
|---|---|---|
| 每章抽出的事实 | 6.40 条 | 6.05 条（旧版约 8.9 条，没有恢复） |
| 都市余额：抽到的章 / 名字统一 | 12 章 / 主名占 79% | 18 章 / 100% |
| 末世进化点：抽到的章 | 18 章 | 19 章 |
| 末世幸存者人数：抽到的章 | 1 章 | 0 章（它从没写过增减，进不了账名提示） |
| 报警 | 6 处 | 14 处，逐条读原文后真有矛盾的 2–3 处 |

账名提示让同一个数叫同一个名字，也抽得更全，但误报也跟着变多了。误报主要有三种：
- 正文写了花掉、得到，但没写成数（「五点，扣得干干净净」），没被抽成一笔增减；
- 一处对不上以后，后面的余额全跟着连环报警；
- 「药品存量」这类说不清单位的数（天数和药片数混在一起）也被当成了账。

### 12.5 结论

**不按原设计做。** 刀 1–5 不开工，0c 不跑，产品代码一行没改。

- 检查器捎带抽数，抽不全一个账需要的每一笔进出；靠这样的账算平，误报比真问题多。这一点换不换账名提示都一样。
- 这批稿子里读者看得出的数值矛盾，主要是「总数忘了、重新从小数起」，比如前面攒到 18 点、这一章写「一共十点」，或者前面 58 点、这一章写「看见的是五个点」。这类错差额很大，但往往没有对应的增减句，按账算不一定落在出错的那一句上。
- 数值和计划不一样、但前后自洽的情况，只有作者对着计划才看得出来。实验里有效的「作者核对过的账」（偏离 19%）靠的是作者在章纲卡片上改数，#531 之后这一步已经没有了。
- **教训也适用于第 ③ 步（知情边界）**：往检查调用里「捎带」新字段并不免费，这次多加一段说明，检查器整体抽事实就少了三成。以后要捎带任何东西，先量它对现有事实抽取的影响。

### 12.6 下一步候选（等作者定）

- **A 停在这里。** 数值账这条线不做，事实台账维持现状。
- **B 只展示，不报警。** 观测镜里按章列出各个数在正文里写成多少，差额特别大的（比如一下少了一大半）标个颜色，作者自己扫一眼。数据直接取台账里已经记下的数值事实，不改检查提示词、不调模型，也不会让批量写章停下。
